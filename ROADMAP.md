# Lumos Roadmap

## Phase 0 — Foundation
Reproducible repository with agent governance, architecture records, CI that runs without credentials, a migration system, and the Model Gateway with a working mock provider.

## Phase 0.5 — Curriculum truth
The registry knows what exists. The canonical chunk schema is defined. The legacy 180 records are normalised, deduplicated, cleaned and re-chunked, with a reviewed report per corpus. Nothing is published until it passes. **This phase exists because the audit found a 5.7× gap between documented and actual corpus size — the fix is to make the system, not a document, the authority.**

## Phase 1 — MVP tutor
A student signs in, selects a curriculum/subject/class that the registry says is available, asks a question in Bangla or English, and receives a streamed, grounded answer with citations that resolve — or an explicit statement that the evidence is insufficient.

## Phase 2 — Learning loop
Past papers, adaptive practice, multi-part question continuity, hints, worked solutions and teacher feedback become first-class. **Gated on BLOCK-001** — past-paper features need past-paper data.

## Phase 3 — Multimodal
Voice and image/document input behind replaceable provider interfaces. Legacy code exists for both.

## Phase 4 — Lumos experience
3D homepage, dark-to-light transition, cursor-reactive light, parallax — with a 2D fallback that keeps every core journey usable without WebGL, and full reduced-motion support.

## Phase 5 — Trust and competition
Golden evaluation set with subject-teacher review, regression suite, security and privacy audit, performance testing on low-end Android profiles, reproducible deployment, technical documentation an external evaluator can follow, and the demo.

## Sequencing rule
Curriculum truth precedes retrieval; retrieval precedes generation; generation precedes experience. Building the homepage before the registry produces a beautiful interface that lies about what it knows.
